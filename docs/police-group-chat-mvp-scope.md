# 公务段群聊功能短期目标与范围限制

## 目标定位

短期目标是在公务段补齐可落地的群聊协作能力，优先服务任务处置、预警响应、现场协作和部门沟通。

本阶段不追求完整 IM 系统体验，重点是让警员能在任务场景下快速发消息、看历史、收未读提醒，并能从工作台和任务相关页面顺畅进入群聊。

## 短期技术限制

- 暂不依赖独立 WebSocket 服务。
- 暂不要求配置自有域名、HTTPS 证书或 `wss://` socket 合法域名。
- 实时能力采用 `uniCloud.callFunction` + 增量轮询实现。
- 群聊页轮询频率建议为 2-3 秒一次。
- 群聊列表页轮询频率建议为 10-15 秒一次。
- 页面隐藏或离开群聊页时停止高频轮询。
- 第一版以文本消息为核心，图片和位置作为可选增强。
- 所有消息必须落库，前端本地状态只作为体验优化。

## 推荐入口

### 工作台入口

现有公务段工作台的“消息中心”入口调整为真正的消息中心。

建议结构：

```text
工作台
  -> 消息中心
      -> 群聊
      -> 通知
      -> @我
```

短期可以先只实现“群聊”列表，把原通知中心保留为后续 Tab。

### 任务入口

任务详情页增加“进入任务群”入口。

```text
任务详情
  -> 进入任务群
```

如果任务尚未创建群聊，可在点击时自动创建任务群，或弹窗确认创建。

## 群聊列表页

页面职责：

- 展示当前警员参与的群聊。
- 展示群名称、群类型、最后一条消息、最后消息时间、未读数。
- 支持按群类型和未读状态筛选。
- 支持搜索群名、警员名、任务标题或任务编号。

建议 UI：

```text
消息中心                         [+]

搜索群名 / 警员 / 任务编号

[全部] [任务群] [部门群] [预警群] [未读]

湿地非法捕猎核查任务群              3
李队：现场照片已上传，请研判
10:32 · 紧急 · 任务中

森林公安局-执勤协作群
王警官：今晚巡护路线已更新
昨天 18:20
```

短期交互：

- 点击群卡片进入群聊详情页。
- 点击右上角 `+` 进入新建群聊流程。
- 未读群靠前展示。
- 高优先级任务群展示红色或橙色标记。

暂缓交互：

- 左滑置顶。
- 免打扰。
- 批量标已读。
- 复杂会话归档。

## 群聊详情页

页面职责：

- 展示群内历史消息。
- 支持发送文本消息。
- 支持轮询增量拉取新消息。
- 支持新消息自动滚动到底部。
- 支持任务群展示关联任务入口。

建议 UI：

```text
<- 湿地非法捕猎核查任务群     5人   ...

系统：任务 T20260617 已创建

李队 10:31
请一组去东侧入口核查

我 10:32
收到，我和王警官已到现场

王警官 10:34
[现场照片] [定位：东侧湿地入口]

底部：
[+]  输入消息...                 [发送]
```

短期底部工具：

```text
[拍照] [相册] [位置] [关联任务] [常用语]
```

短期常用语：

- 已到达现场
- 正在核查
- 请求支援
- 已控制现场
- 需补充取证
- 任务完成，等待复核

暂缓工具：

- 语音消息。
- 输入中状态。
- @成员。
- 消息已读回执。
- 表情面板。
- 文件传输。

## 新建群聊流程

短期支持三类群：

- 任务群：关联某个任务，服务任务处置。
- 部门群：部门内日常协作。
- 临时处置群：不一定绑定任务，用于临时事件沟通。

建议流程：

```text
新建群聊
  1. 选择群类型
     [任务群] [部门群] [临时处置群]

  2. 填写群名称
     默认可使用任务标题 + 群

  3. 选择成员
     按部门 / 按警员 / 最近协作

  4. 关联任务
     任务群必填，其他类型选填

  5. 创建
```

从任务详情页创建任务群时，自动带入：

- 任务 ID。
- 任务标题。
- 当前警员。
- 任务负责人。
- 已分配协作人员。

## 数据模型建议

### chat_rooms

用于保存群聊房间。

核心字段：

- `_id`
- `name`
- `type`
- `task_id`
- `dept`
- `created_by`
- `member_ids`
- `last_message`
- `last_message_time`
- `create_time`
- `update_time`

### chat_messages

用于保存消息。

核心字段：

- `_id`
- `room_id`
- `sender_id`
- `sender_name`
- `sender_badge_no`
- `message_type`
- `content`
- `file_url`
- `location`
- `task_id`
- `client_msg_id`
- `status`
- `create_time`

### chat_room_members

用于保存成员关系和未读状态。

核心字段：

- `_id`
- `room_id`
- `officer_id`
- `officer_name`
- `role`
- `last_read_time`
- `joined_at`
- `mute`

## 云函数建议

新增 `gw-chat` 云函数。

短期 action：

- `getRoomList`
- `getMessageList`
- `sendMessage`
- `createRoom`
- `getRoomDetail`
- `markRead`
- `addMembers`

短期调用约束：

- 所有 action 都必须校验 `officer_id`。
- 读取房间和消息前必须校验成员关系。
- 发送消息前必须校验发送者属于该群。
- `sendMessage` 成功后更新 `chat_rooms.last_message` 和 `last_message_time`。
- 客户端用 `client_msg_id` 做幂等，避免弱网重复发送。

## 前端状态逻辑

发送消息流程：

```text
用户点击发送
  -> 前端立即插入一条 status=sending 的本地消息
  -> 调用 gw-chat/sendMessage
  -> 成功后替换为云端消息，status=sent
  -> 失败后标记 status=failed，可点击重发
```

拉取消息流程：

```text
进入群聊页
  -> getMessageList 拉最近 20 条
  -> 记录 lastMessageTime
  -> 每 2-3 秒拉取大于 lastMessageTime 的新消息
  -> 合并去重
  -> 更新 lastMessageTime
  -> markRead
```

离开页面：

```text
onHide/onUnload
  -> 清理轮询定时器
```

## 安全与审计限制

- 不能只相信前端传入的 `room_id` 和 `officer_id`。
- 云函数必须校验当前警员是否为群成员。
- 消息短期不做物理删除。
- 撤回功能短期不做；后续如实现，只改变消息状态。
- 群聊消息属于执法协作记录，默认应可审计。
- 不在前端保存敏感密钥。

## 验收标准

第一版完成后，应满足：

- 警员能从工作台进入群聊列表。
- 警员能进入某个群聊查看历史消息。
- 警员能发送文本消息。
- 同一群内其他警员能在 2-3 秒内看到新消息。
- 群聊列表能显示最后一条消息和未读数。
- 从任务详情能进入或创建任务群。
- 页面离开后不会继续高频轮询。
- 云函数会拦截非群成员读取或发送消息。

## 明确非目标

短期不做：

- 独立 WebSocket 服务。
- 自有域名和证书配置。
- 真正毫秒级实时通信。
- 在线状态。
- 输入中提示。
- 已读人数详情。
- 语音通话或视频通话。
- 复杂组织通讯录。
- 全量 IM 后台管理系统。

## 实施建议

建议按以下顺序开发：

1. 新增 `gw-chat` 云函数和数据库 schema。
2. 实现群聊列表页，替换或扩展现有消息中心。
3. 新增群聊详情页，实现文本消息和轮询。
4. 接入任务详情页的“进入任务群”入口。
5. 增加未读数和 `markRead`。
6. 可选增加图片和位置消息。
7. 后续再升级 WebSocket 与离线推送。
